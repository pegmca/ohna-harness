# ohna 工作区切换修复与 Codex / Claude 对齐用例（第二批）

日期：2026-10-31
范围：`apps/ohna-desktop` 工作区会话上下文、编码 Agent 日常操作体验
目标：固定本次工作区切换缺陷的回归边界，并继续收集 10 条可判定的对齐用例。

## 本次缺陷与修复

### BUG-WS-001 已存在会话中切换或添加工作区后仍停留旧会话

**现象**

1. 打开任一会话。
2. 在 composer 上方切换工作区，或在侧栏添加工作区。
3. 工作区路径更新，但标题、消息时间线和 URL 仍指向旧会话。

**根因**

`handleSelectWorkspace` / `handlePickWorkspace` 只更新 `activeWorkspaceId`。
`activeConversationId`、消息、URL `?conversation=`、replay 与草稿输入属于另一条会话状态流，
没有随工作区上下文变化而重置。

**修复契约**

- 切换已授权工作区成功后，进入全新会话草稿。
- 添加并授权工作区成功后，进入全新会话草稿。
- 草稿态要求：标题“新会话”、消息为空、URL 为 `#/`、composer 输入为空、无旧确认卡片和 replay。
- 侧栏历史仍展示各工作区的历史会话；“当前工作区”只决定下一次新会话归属，不删除或隐藏旧历史。
- 已提交的 Run 不因 UI 切换被隐式取消。

**自动回归**

- `switching workspace opens a fresh conversation draft instead of keeping the current history`
- `adding a workspace also opens a fresh conversation draft`

## 第二批对齐用例

### UX-101 工作区切换防竞态

**对齐**：Codex 多项目切换不会把旧项目响应写进新项目。

**步骤**
1. 打开工作区 A 的历史会话，触发行程较慢的历史消息加载。
2. 在响应返回前切换到工作区 B。
3. 等待原请求完成。

**预期**
- 当前视图保持 B 的新会话草稿。
- A 的迟到响应不得回填标题、消息、确认卡片或 runner 状态。
- URL 不重新写回 A 的 conversation id。

**判定信号**：AI 请求迟到完成时，DOM 中不出现 A 的独有文本；`window.location.search === ""`；
无 `running` 残留；控制台无 abort 导致的未处理错误。

### UX-102 草稿切换保护

**对齐**：Claude / Codex 在切换会话或项目时不静默丢弃未发送文本。

**步骤**
1. 在新会话草稿中输入一段未发送文本。
2. 切换工作区或点击历史会话。
3. 选择返回原草稿或确认丢弃。

**预期**
- 有非空草稿时出现明确确认，或自动保留可恢复草稿。
- 取消操作后文本、光标与当前工作区保持。
- 确认丢弃后目标会话完整加载。

**判定信号**：切换前草稿长度 > 0；取消后 textarea 值完全相等；确认后 URL 与目标 conversation 匹配。

### UX-103 Composer 焦点与快捷键

**对齐**：Codex 常用键盘流不需要频繁点鼠标。

**步骤**
1. 打开会话。
2. 使用约定快捷键聚焦 composer。
3. 输入文本、打开模型菜单、用方向键选择并按 Enter。
4. 按 Escape 回到编辑器。

**预期**
- 焦点进入 textarea，不误触发送。
- 菜单内方向键移动活动项，Enter 选择，Escape 只关闭菜单。
- 菜单关闭后焦点回到模型触发器或编辑器中的明确位置。
- Shift+Enter 换行，Enter 发送。

**判定信号**：`document.activeElement` 的可访问名、`aria-activedescendant`（若采用）、
模型选择回调次数、消息事件次数；全程无鼠标操作。

### UX-104 长对话滚动跟随与回看保护

**对齐**：Claude 流式回答仅在用户位于底部时自动跟随。

**步骤**
1. 产生长对话并滚动到中上部。
2. 在另一个会话触发流式回答，随后切回。
3. 再滚动到底部继续接收增量。

**预期**
- 用户回看历史时，新增 token 不强制把视口拽到底部。
- 位于底部时恢复跟随。
- 新消息插入不抖动，不遮挡 composer。

**判定信号**：记录 `scrollTop`、`scrollHeight`、`clientHeight`；回看时 `scrollTop` 变化小于阈值，
底部时距底小于 80px；无横向溢出。

### UX-105 停止、失败与重试的状态闭环

**对齐**：Codex 的中断与失败会明确收敛，且可重试。

**步骤**
1. 发起一个长回答，在流式过程中点击停止。
2. 发起一个 provider 失败请求。
3. 分别点击重试。

**预期**
- 停止后状态为 cancelled；失败后为 failed，不出现伪造 completed。
- 停止后不继续追加 token；失败正文只展示一次真实错误。
- 重试复用原输入与模型，生成新 run，不与旧 run 终态混淆。

**判定信号**：run JSONL 终态、`requestId` 变化、`clientMessageId` 策略、DOM 错误出现次数。

### UX-106 刷新与崩溃恢复

**对齐**：Claude / Codex 刷新后保持会话选择与可恢复的运行状态。

**步骤**
1. 在指定会话内触发运行并刷新页面。
2. 模拟异常退出后重新打开。
3. 打开 Trace，选择最后 run。

**预期**
- URL 指定会话优先恢复，而非跳到列表第一条。
- 进行中 run 最终收敛为 interrupted / failed / completed 之一。
- 已持久化消息、Trace 事件和确认卡片可重建。
- 不显示永久 running。

**判定信号**：刷新前后 conversation id 相同；run 快照为终态；replay 事件序列无重复；
`ohna-runtime.lock` 在正常退出后不存在。

### UX-107 侧栏与标题的密集状态

**对齐**：Codex 长项目名称与多会话堆叠仍可扫描。

**步骤**
1. 创建两个长 workspaceId、十个长会话标题。
2. 检查 hover、active、archived 和超长标题。
3. 用键盘 Tab 遍历侧栏。

**预期**
- 组名、标题单行省略，归档按钮始终可见。
- 无页面横向滚动。
- active 与 hover 可用文字/图标区分，不只依赖颜色。
- 归档后焦点移动到合理下一项，不落入已移除 DOM。

**判定信号**：`scrollWidth`、标题 `text-overflow`、归档按钮矩形与命中区域、焦点元素的 `aria-label`。

### UX-108 错误空态与恢复入口

**对齐**：Claude 的空态与失败态给下一步，不只给错误文本。

**步骤**
1. 模拟工作区列表、模型目录、设置读取分别失败。
2. 检查各失败态。
3. 恢复依赖后点击重试。

**预期**
- 工作区 / 模型 / 设置失败有各自明确范围，不互相伪装为成功。
- 重试只重做失败资源，不重建已加载会话。
- 无数据空态不等于错误态。

**判定信号**：错误 role、错误文案、对应 SDK 调用次数；恢复后同一 DOM 区域切换为空态或内容态。

### UX-109 设置改动的影响范围

**对齐**：Codex 设置保存后明确何时生效，不悄悄影响在途任务。

**步骤**
1. 在一个 run 进行中修改默认模型、provider baseUrl 或代理。
2. 保存并观察当前 run、下一 run 与重启后。

**预期**
- 当前 run 保持创建时配置快照。
- 保存提示“重启后生效”时，不伪装成已热切换。
- 下一 run 的模型目录与配置来源一致；重启后模型与代理真实生效。
- settings `.json` 权限仍为 `0600`，不改仓库文件。

**判定信号**：run snapshot 的 modelId、`llm_call.window`、settings mtime/mode、
重启前后 composer 默认模型、`cost_summary.byModel`。

### UX-110 权限确认的键盘与超时

**对齐**：Codex 变更操作可键盘处理，拒绝也能安全收敛。

**步骤**
1. 触发 write / bash 工具确认。
2. 用键盘聚焦允许与拒绝，分别执行。
3. 再次触发等待超时或取消 run。

**预期**
- 确认卡片有明确焦点顺序与可访问名。
- 拒绝后工具结果为 error，但 run 能继续给出可读结果。
- 允许后工具真正执行；超时或取消后卡片不悬挂。
- 刷新可恢复未决确认，已决确认不再次出现。

**判定信号**：`confirmation_requested` / `tool_execution_end` 事件数量与配对、
文件副作用、run 终态、卡片 `aria-live` 与焦点位置。

## 执行建议

按以下顺序逐步完善，避免一次改动同时重写多个状态机：

1. 先修工作区切换的会话上下文一致性（本次已完成并补回归）。
2. 再补 UX-101 / UX-102：迟到响应与草稿保护。
3. 补 UX-103 / UX-104：键盘流与滚动跟随。
4. 补 UX-105 / UX-106：中断、失败、刷新恢复的终态闭环。
5. 最后补 UX-107 至 UX-110：密集侧栏、错误空态、设置影响范围与权限确认。

每个用例落地时同时提交：DOM/交互回归测试、真实窗口操作记录、必要的几何断言与截图路径。
